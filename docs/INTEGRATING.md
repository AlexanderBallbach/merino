# Integrating an app with Merino

Two shapes exist today. Pick by where your reports already live.

| Shape | Use when | Example |
|---|---|---|
| **Standalone realm** | The app has no report store; Merino is the store | LiftCharge / Storm Spotter (`python -m merino serve`, SQLite) |
| **Ledger layer** | Reports already live in your Postgres | Aether Atlas (`sql/merino.sql` + triggers + `pg-sign`) |

Either way: apps share code, **never accounts or data**. One realm per app.

## 1. Add a standalone realm

1. In `python/merino/policy.py` add a `Realm`:
   - `time_gran` (minutes, SPEC 5), `min_prec` (smallest allowed cell in metres
     per kind), `body` validator (`callable(kind, body)` → `None` or an error
     string; always allow `delete/flag/confirm` bodies of `None` or `{fh, scope}`),
   - `retention_days` (0 = keep), `media_max`, `media_per_item`, `media_days`
     (per-mime media retention), `rate` limits.
   Register it in `REALMS`.
2. `python3 -m merino keygen --keys /etc/merino --realm <name>` (prints the
   public key; keep the seed out of git and out of backups that leave the host).
3. Run `merino serve … --realms <name> --prefix /api/merino` under systemd with
   the hardening in `OPERATIONS.md`, plus an hourly `merino purge` timer.
4. Put it behind a proxy that passes `X-Real-IP` and does **not** log
   client addresses or query strings.
5. Add tests in `python/tests/` and, if you changed rules, regenerate vectors
   (`python3 tools/gen_vectors.py`) and re-run every implementation against them.

## 2. Add the Postgres ledger layer

1. Apply `sql/merino.sql` (idempotent) to your database.
2. Add triggers like the Atlas ones: an *immutability* trigger on tables whose
   geometry must not change once public, and an `AFTER INSERT OR DELETE` trigger
   calling `merino.ledger_append(realm, kind, subject, merino.minute(now(), gran),
   'sys:<app>')` where `subject = sha256(c14n({t, id, g: sha256(geometry)}))`.
   Never put user ids or content into the ledger.
3. Create the realm key on a host that is **not** the database host
   (`merino keygen`), and run `merino pg-sign` from a timer. The signer needs
   only a `psql` pipe to the DB.
4. Verify end to end with `sql/test.py` and by auditing the published ledger.

## 3. The client (Kotlin, JVM/Android)

`kotlin/src/main/kotlin/org/merino/*.kt` is pure Kotlin with no Android
dependency: grid reduction, keyed rounding, paths/polygons, media cleaning,
c14n, Ed25519 signing, envelope building. **Vendor it by copying**, don't fork:

- Copy the files into your app under `org/merino/` and add the header comment
  `// Vendored from merino <git sha>. Do not edit here; change Merino and re-copy.`
- Run `cd kotlin && ./gradlew -q vectors` to confirm the Kotlin engine still
  matches `vectors/` after any change.
- Currently vendored in LiftCharge (`org/merino/*.kt`) and Field Companion
  (`Geo.kt`).

## 4. Conformance vectors

`vectors/*.json` (c14n, ed25519, envelope, keyed, ledger, lon_mult, media,
paths, points, polygons, snaps) are generated by `tools/gen_vectors.py` from the
Python engine (set `MERINO_MP4=/path/to/sample.mp4` to include the mp4 media
vector, otherwise regenerating drops it: `git checkout vectors/media.json` if so) and consumed by the Python tests, the Kotlin `vectors` task, and
the SQL port's `sql/test.py`. A new implementation is conformant when it
reproduces every vector byte-for-byte. Change a rule in SPEC first, update
Python, regenerate, then fix the other implementations until they pass.

## 5. Checklist before shipping an integration

- [ ] Nothing leaves the device more precise than the realm's `min_prec`.
- [ ] No IPs, install ids, emails or user ids in any table, log or ledger row.
- [ ] Deletes erase content (`wire`/row body) and media; only the hash remains.
- [ ] Placed geometry is immutable (envelope `ref` edits must repeat `geo`).
- [ ] Realm key is outside the database and outside git.
- [ ] `merino audit` passes against the public endpoint.
- [ ] The (i)/privacy page of the app states what is public (rule zero).
